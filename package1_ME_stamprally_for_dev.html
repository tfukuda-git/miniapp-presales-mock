ME連携 スタンプラリー＋抽選 ミニアプリ（モデルハウス）

ME-linked Stamp Rally + Lottery Mini App — Package definition + UI mock in one file

Premise：ME導入済みクライアント向けスタンプラリー（PKG①）に抽選機能を統合した強化版。ME（Mico Engage）テナント上に相乗りするLIFFミニアプリ。スタンプ本数・抽選参加・当落・実施日時はMEのカスタム属性に書き込み、集計と後追い配信はME側で実施。スタンプ単発（3ヶ月）で終わらず、抽選を3ヶ月スパンで継続実施することで月額（MRR）契約の根拠を作る。

位置づけ・対象 Positioning / Target

  • 対象：ME導入済みクライアント（不動産＝モデルハウス／展示場／住宅フェア 等）
  • ME既存顧客への「アップセル・オプション」として提供（求人マッチングと同じ売り方）
  • スタンプラリー＋抽選を1パッケージ化し、不動産業界へ横展開 → 原価を1社に集中させない
  • 初号案件：ミサワホーム様（現行はスタンプ＝RALLY単発、抽選＝専用フォームで別運用）

前提条件 Assumptions

  • クライアントがME導入済み・LINE公式アカウント保有
  • スタンプ・抽選・属性データはMEの既存の仕組みに連携（自前DB・管理画面・精算ロジックは持たない）
  • 景品の現物手配・抽選の景品入替（3ヶ月スパン）はクライアント運用

アーキテクチャ（シンプルさのキモ）Architecture

QRでスタンプ取得→ スタンプ状況を ME属性に書込→ 完走 → 抽選応募→ 抽選実行・当落を ME属性に書込→ ME上で集計→ 未達者・落選者へ ME後追い配信

専用バックエンド・管理画面・精算ロジックは新規開発せず、ME側の属性＆配信基盤に相乗り。求人マッチングの「スワイプ→属性」を「スタンプ／抽選→属性」に置き換えた構成。抽選ロジック（応募・抽せん・当落判定）もカスタム属性とイベントで完結する軽量実装。

含む機能（MVP）In scope

  • 流用友だち追加ゲート（LIFF）
  • 流用初期アンケート（スワイプUI）→ カスタム属性
  • 流用QR読取 → スタンプ付与 / スタンプカードUI
  • 流用会場ごとの重複チェック（同一会場は1回）
  • 抽選スタンプ完走 or 来場で抽選に応募
  • 抽選抽選実行・当落表示
  • 抽選当選引換（スタッフ操作画面）
  • 流用スタンプ／抽選状態を ME属性へ書込＋イベント発火

含まない（ME側 or 対象外）Out of scope

  • 自前の集計ダッシュボード／管理画面 → ME側で対応
  • 景品の在庫・物流・配送管理
  • フェア飛び込み来場者の個人情報のLINE一元化（紙運用のまま・別フェーズ）
  • 多言語フル対応・地図／回遊クーポン
  • 多テナント管理（クライアント個別導入のため）

不正対策の方針 Anti-fraud

不正は一定発生する前提で「メリット＞不正リスク」に設計。スタンプ特典はその場完結（来場特典）＋会場ごとのユニークQR＋ユーザー単位の重複チェック。抽選はユーザー単位で1キャンペーン1応募に制限し、当落・引換状態をME属性で管理することで二重当選・二重引換を防止。
