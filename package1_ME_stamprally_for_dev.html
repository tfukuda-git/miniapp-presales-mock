ME連携 スタンプラリー＋抽選会 ミニアプリ（モデルハウス）

ME-linked Stamp Rally (tiered rewards) + Year-round Lottery — Package definition + UI mock in one file

Premise：ME（Mico Engage AI）テナント上に相乗りするLIFFミニアプリ。スタンプラリーは段階的景品（1個/2個/3個…で景品付与）のシンプル設計。抽選会は通年化の別施策として同基盤で実施（景品3ヶ月入替）。スタンプ・景品・抽選・行動データはすべてME AIのカスタム属性に蓄積し、集計・エリア別配信・ナーチャリングはME AI側で実施。専用管理画面は持たない。

位置づけ・対象 Positioning / Target

  • 対象：ME導入済みクライアント（不動産＝モデルハウス／展示場／住宅フェア 等）
  • ME既存顧客への「アップセル・オプション」（求人マッチングと同じ売り方）
  • 不動産向けに横展開し、開発原価を1社に集中させない
  • 初号案件：不動産クライアント様（総合展示場・モデルハウスの多拠点運用を想定）

アーキテクチャ（シンプルさのキモ）Architecture

QRでスタンプ取得→ 段階的景品を付与（1/2/3個…）→ 状態を ME属性に書込→ ME集計・エリア別配信→ 未達者へ ME後追い配信

抽選会（通年・別施策）も同じME基盤で実施し、当落・応募状態を属性に蓄積。専用バックエンド・管理画面・精算ロジックは新規開発せず、ME側の属性＆配信基盤に相乗り。求人マッチングの「スワイプ→属性」を「スタンプ／景品→属性」に置き換えた構成。

含む機能（MVP）In scope

  • 新エリア選択（ミニアプリ内で選択／配信からも誘導）
  • 流用初期アンケート（フォームで回収）→ 属性
  • 流用QR読取 → スタンプ付与／スタンプカード
  • 新段階的景品付与（1個/2個/3個…で景品）
  • 新状態別QR制御（4個目はスタッフ提示QRのみ・軽微な実装）
  • 新スタンプが押せる場所一覧（エリア別出し分け）
  • 新拠点ごとの注意事項 出し分け
  • 流用会場ごとの重複チェック
  • 流用抽選会（通年・別施策、景品3ヶ月入替）
  • 流用状態を ME属性へ書込＋後追い配信

含まない（ME側 or 対象外）Out of scope

  • ミニアプリ専用の管理画面・エリア別権限管理画面 →（別途検討・実施時期は未定。10月はオペレーションで対応）
  • 住所テキストからの自動エリア判定 →（開発要のため、配信でエリア選択を促す方式に）
  • 自前の集計DB／景品の在庫・物流・配送管理
  • フェア飛び込み来場者の個人情報のLINE一元化（紙運用のまま・別フェーズ）

不正対策の方針 Anti-fraud

不正は一定発生する前提で「メリット＞不正リスク」に設計。会場ごとのユニークQR＋ユーザー単位の重複チェック。1〜3個目は来場（展示場・モデルハウス見学）でQR取得可、4個目はスタッフが相談後に提示するQRでのみ取得とし、状態別QR制御で来場・相談後のみ加算されるよう制御（属性条件で加算可否を判定する軽微な実装。最終確認はインド開発チーム）。

3裏側のしくみ（ME連携・管理）Backend

専用管理画面を持たず、導入済みの Mico Engage AI に相乗り

スタンプ取得・段階的景品の付与・抽選会の応募/当落・エリアなどの状態は、すべてME AIのカスタム属性に書き込み。リアルタイムの閲覧・セグメント抽出・CSVダウンロードはME AI画面で行います。エリア別の管理画面・権限分けは別途検討（実施時期未定）とし、10月はオペレーション（エリア選択方式・拠点別出し分け）で対応します。
