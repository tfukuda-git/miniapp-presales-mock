ME-linked Stamp Rally Mini App — Package definition + UI mock in one file
Premise: standalone LIFF mini app that rides on an existing Mico Engage (ME) tenant. Stamp status is written to ME custom attributes; aggregation & follow-up messaging happen in ME. Same level as the Job-Matching mini app.

位置づけ・対象 Positioning / Target

  • 対象：ME導入済みクライアント（不動産＝モデルハウス／展示場 等） — clients who already use ME
  • ME既存顧客への「アップセル・オプション」として提供
  • スタンプラリー需要が高い業種に横展開（求人と同じ売り方）

前提条件 Assumptions

  • クライアントがME導入済み・LINE公式アカウント保有 — ME + LINE OA in place
  • スタンプ・属性データはMEの既存の仕組みに連携 — stamp/attribute data flows into ME

アーキテクチャ（シンプルさのキモ）Architecture — keep it simple

QRでスタンプ取得 / Scan QR→ スタンプ状況を MEカスタム属性に書込 / write to ME attribute→ ME上で集計 / aggregate in ME→ 未達者へ MEで後追い配信 / follow-up push

自前の集計DB・管理画面・精算ロジックを持たず、ME側の属性＆配信基盤に相乗り。求人マッチングの「スワイプ→属性」を「スタンプ→属性」に置き換えた構成。 No bespoke backend/admin/settlement — reuse ME. Same pattern as Job-Matching (swipe→attribute → stamp→attribute).

含む機能（MVP）In scope (MVP)

  • 友だち追加ゲート（LIFF） — friend-add gating
  • 初期チュートリアル（任意・軽い説明） — light tutorial
  • QR読取 → スタンプ付与 — QR scan → award stamp
  • スタンプカードUI（進捗・コンプリート） — stamp card
  • コンプリート → 特典クーポン表示 — completion → reward
  • スタンプ／完了状態を ME属性へ書込＋完了イベント発火 — write to ME + fire event

含まない（ME側 or 対象外）Out of scope

  • 自前の集計ダッシュボード／管理画面 → ME側で対応 — handled by ME
  • 店舗別の精算・金銭バック — no cash settlement
  • 多言語フル対応・地図／回遊クーポン — no map/coupon-rally
  • 多テナント管理（クライアント個別導入のため） — single-tenant per client

不正対策の方針 Anti-fraud

不正は一定発生する前提で「メリット＞不正リスク」に設計。特典はその場で完結（来場特典）＋会場ごとのユニークQR＋ユーザー単位の重複チェックで対応。 Assume some fraud; design so benefit > loss. Unique per-venue QR + per-user de-dup; same venue counts once.
